# FOUR · 本地 4 键音游白模

已实现 D / F / J / K 四轨下落、单点、多押、长条、音乐同步、Perfect / Great / Good / Miss、分数、准确率、连击、暂停重开、结算、本地最高分、自动演示，以及听歌实时打谱和可视化精修。内置 4 张合成音乐练习谱，以及 Dareharu《Karma》的上游示例谱。

## 运行

- **直接双击 `index.html`**，用 Edge 或 Chrome 打开，即可离线游玩。无需安装依赖。
- 或双击 **`start.bat`**，启动本地服务并打开 `http://127.0.0.1:4173`。关闭终端即可停止服务。如果没有 Node，会退回直接打开 HTML。
- 开发时运行 `node server.cjs`（或已安装 npm 时运行 `npm start`）。服务只监听本机，不连接外部网络。端口被占用时，可在 PowerShell 中设置 `$env:PORT=4174` 后运行服务。

点击「开始练习」解锁浏览器音频。音符中心落到白线时按对应按键；也可点击轨道底部的 D / F / J / K 按钮。Space 开始 / 暂停，Esc 暂停 / 继续；表单输入焦点下保留表单原有键盘操作。轨道上方提供暂停、重开与「放弃 / Q」按钮；放弃立即停止音乐并回到准备状态，本次成绩不保存。音频准备过程中也可放弃，后续解码完成不会重新开始。切换窗口或标签页会自动暂停。开局预留至少 2 秒，谱面从音乐开始的位置计算时间。

音符下落速度可在 **0.40×–3.00×** 之间调整，默认 **2.50×**，倍率越大越快。音符从顶部出现到判定线的可见时长已在同倍率下翻倍：使用 `3.6 秒 / 倍率`，默认 2.5× 为 1.44 秒（此前相同 2.5× 为 0.72 秒）。可以在打歌中实时拖动滑条，或按 **F1 减速 / F2 加速**，每次调整 0.1×。这只改变音符的视觉移动，不改变歌曲速度和判定时刻。判定偏移为正时，音符到达白线与可击打时间一起延后。音量也可在游戏中调整。暂停后可继续、重新开始或放弃；其他谱面设置在游玩结束后修改。自动演示不保存成绩。

游玩轨道采用细长比例，桌面轨道宽度上限 420 px、高度随窗口增加至最多 1100 px；小窗口时重新排列设置与统计面板。长条头尾与节拍线使用相同的加长视野时间，保证落到判定线的时刻一致。编辑时间轴高度为 460 px。

| [juneekim7/rhy-game](https://github.com/juneekim7/rhy-game) | MIT；轻量 HTML/JS 音游库，有 4 键范例、可配置判定和谱面 | 主要参考；实际移植 `Judgement` 模型，改编 `Note.judge` 的时间窗判断，借鉴谱面与玩法分离 |
| [ChloeLiang/rhythm-game](https://github.com/ChloeLiang/rhythm-game) | MIT；纯 HTML/CSS/JS，README 说明音符动画写死 | 调研参考；没有移植代码和歌曲 |
| [koneko/4koneko](https://github.com/koneko/4koneko) | 符合 4 键需求，但 README 明确没有许可证 | 没有移植代码 |
| [Quaver/Quaver](https://github.com/Quaver/Quaver) | 完整的社区音游，包含线上功能 | 范围比本地白模大，没有引入 |

上游固定版本为 `7b267a92321da756578a9f5cf777c2247fb89f52`。原始源码、分发 JS、README、示例谱代码和 MIT 许可证保存在 `vendor/rhy-game/`。复用的判定模型在 `vendor/judgement.js`；没有直接沿用上游整个 `Game`：原实现使用 Date 与 setTimeout 驱动，并在每次 play 时绑定事件；当前白模用 AudioContext 的同一时钟驱动音频、渲染与判定，以便可靠暂停重开。

公开仓库仅保留《Karma》的示例谱面；音乐需自行提供，可选的本地音频不上传 Git。上游原谱只是约 10 秒的片段，四轨共 42 个音符，其中 2 个长条。可选的本地原曲放在 `assets/karma.mp3`，转换谱在 `charts/karma.json`，用上游 `delay: -450` 换算出 450 ms 的首拍基准，保留原音符时间。上游 README 明确说明不拥有音乐版权，歌曲不属于源码 MIT 许可，详见 `assets/README.md` 与 `THIRD_PARTY_NOTICES.md`。

## 听歌打谱 / 精修

1. 点击「听歌打谱」，导入本地歌曲；也可在本地提供可选 Karma 音频后点击「载入 Karma 原谱与音乐」。公开仓库仅提供示例谱面，未提供音频时会提示自行导入。
2. 设置 BPM 和「首拍位置 / ms」。例如 120 BPM 时，每拍 500 ms，1/8 网格间隔 250 ms，1/16 网格间隔 125 ms；这不是 8 / 16 个拍子的分组。BPM 与首拍位置需要手动设置，本阶段不自动分析音乐。
3. 设定起止秒数，选择「追加」或「覆盖」。点击录制后先播放两拍准备段，进入区间才开始记录 D / F / J / K。短按生成单点，按住至少 180 ms 生成长条，多个键可以一起按。长条起点和终点都会吸附到最近网格。关闭吸附可保留原始时刻；录入补偿为正时会把敲击时间提前。
4. 区间终点、Esc、停止按钮、切换页面或窗口失焦会结束本次录制并保留已录入音符。覆盖只作用于实际录制过的区间，删除与该区间相交的旧音符（跨边界长条也会删除）；其余区间保留。吸附后同轨重复 / 相交音符合并，不同轨多押保留。可撤销本次录制。
5. 时间轴横轴为时间，四行对应 D / F / J / K，顶部显示歌曲波形。选择工具可拖动音符时间 / 轨道，拖动长条尾部改长度；添加单点、绘制长条、删除均有独立工具。点击上方标尺定位试听；下方滑条滚动，缩放菜单放大。
6. 选中音符后可输入轨道、起点和终点毫秒数进行精修，终点留空变成单点。数字输入保留精确毫秒，不自动吸附。方向键按一个网格微调（Shift 为 1 ms），Delete 删除；Ctrl+Z / Ctrl+Shift+Z 撤销 / 重做。手动修改造成同轨重叠会提示错误，不静默删除其他音符。「按当前网格整理全部」重新吸附并合并冲突。
7. 「游玩测试本段」把当前所选区间的音频与音符一起截取，立即转到白模测试，避免每次从歌曲开头播放。导出 JSON 则保留整张谱面。

「歌曲播放速度」提供 **0.25× / 0.50× / 0.75× / 1.00×**，同时用于录制与试听。开始前选择倍率，结束本段后可再次调整。音符仍保存为原曲毫秒时间：例如半速听到原曲第 10 秒时敲键，记录的仍是第 10 秒，原速游玩不会错位。节拍器、准备段、录入补偿都会按倍率换算；长条仍按现实时间按住至少 180 ms 识别。当前使用 Web Audio 重采样慢放，音调会随速度降低，尚未实现保持原音调的时间拉伸。游玩模式保持歌曲原速，下落速度另行调整。

草稿自动存入本浏览器 localStorage，最多 50 步撤销（撤销历史不跨刷新保存）。自选音频不存入草稿，刷新后重新导入歌曲；Karma 草稿刷新后再次载入音乐，会保留草稿修改。JSON 不包含自选音频，保存时请同时保留原歌曲。暂无自动 BPM 检测、变速 BPM、多音符框选或滑键。

## 谱面格式

```json
{
  "version": 1,
  "keys": 4,
  "title": "我的练习谱",
  "bpm": 120,
  "gridOffset": 0,
  "duration": 10000,
  "notes": [
    { "time": 2000, "lane": 0 },
    { "time": 2500, "lane": 1 },
    { "time": 3000, "lane": 2 },
    { "time": 3000, "lane": 3, "endTime": 4500 }
  ]
}
```

`time`、`endTime`、`duration` 和可选的 `gridOffset` 单位均为毫秒；`lane` 0 / 1 / 2 / 3 对应 D / F / J / K。没有 `endTime` 为单点，存在且大于 `time` 为长条。同一时刻不同轨表示多押；同轨同时间重复音符及长条区间里的其他音符会被拒绝。长条结束的同一时刻可以开始下一个音符。谱面可以不排序，导入时自动排序。BPM 用于节拍线和合成伴奏，音符以绝对毫秒时间为准。可选 `audioId: "karma"` 关联内置 Karma；自选音乐不写文件路径。当前限制为 10 分钟、20000 音符、3 MB JSON、100 MB 音频。

自定义歌曲：导入 JSON，再选择本地 MP3 / WAV 等浏览器支持的音频。谱面时间以音频起点为零，音乐长度应至少等于 `duration`。音乐不会自动生成谱面；打谱器根据你的按键生成。点击「恢复谱面音乐」可以返回谱面自带音乐。导出的 JSON 不包含音频，刷新页面后需重新选择自定义文件。所有文件只在本机读取；本地最高分由浏览器 localStorage 保存，换浏览器或清理站点数据后不共享。

满分 1000000；Perfect / Great / Good 权重为 1 / 0.75 / 0.5，Miss 为 0。准确率为已判定音符的平均权重；最终结算覆盖全部音符。每个时间窗包含边界，范围分别为 ±45 / ±90 / ±140 ms。空按不扣分，过早击打不消耗音符，漏击打断连击。

## 验证

运行 `node --test tests/*.test.cjs`。测试覆盖点击与长条判定、提前松键 / 漏头、多押、计分、音频时钟、慢放暂停继续与时间换算、慢放长条识别、8 / 16 分吸附、分段覆盖、录入冲突合并，以及本地资源服务。音频输出延迟受设备影响，实际手感可用判定偏移、录入补偿调整。
